# Bağımsız kurulum ve sürüm güncelleme

Bir kopya = tek PT, PT'nin kendi Vercel projesi ve kendi private GitHub veri repoları. DB yok. Geliştiricinin sunucusu, Vercel Integration kaydı, ortak OAuth anahtarı veya tokenı yok. Sadece PT'nin isteğe bağlı sürüm kontrolü/güncellemesi sabit upstream `gokerlek/axon-fit` reposunu okur.

Eksik env'de yerel `/install` sihirbazı açılır. Kod reposu Vercel bağlantısından alınır, yayın dalı main ve veri repo adı otomatik seçilir. PT yalnız GitHub PAT ve giriş uygulaması anahtarlarını yapıştırır; GitHub kullanıcı adı PAT ile otomatik doğrulanır. Sihirbaz kalıcı domain'den callback adresini gösterir, benzersiz AUTH_SECRET üretir; Gemini anahtarı opsiyoneldir. Değerler açık sekmede tutulur ve kalıcı tarayıcı depolamasına yazılmaz. Otomatik yol PT'nin kendi geçici Vercel tokenını yalnız işlem boyunca kullanır. Kendi uygulamasının server'ı kendi VERCEL_PROJECT_ID projesine Production env yazar ve yeni Git deployment başlatır. Proje/repo/owner/token izinleri kontrol edilir; mevcut sırlar ezilmez, Vercel tokenı kalıcı tutulmaz. Alternatif .env metni/dosyası tamamen tarayıcıda hazırlanır ve manuel aktarılır.

Yeni yayının env durumunu okuyan ekran hazır olduğunda normal GitHub girişine geçer. Sadece beklenen owner oturum açar. Görünüm seçilebilir veya atlanabilir; kayıt ilk private veri repo'sunu hazırlar. Başarı ekranından danışan eklemeye geçilir.

Güncelleme: PT oturumu + same-origin POST + açık üzerine yazma onayı. Kararlı semver release ve manifest gerekir. Actions PT'nin kendi kod reposunda geçici bir dalda yeni sürüm ağacını hazırlar; workflow dosyalarını korur. Sunucu yalnız başarılı hazırlığın tek parent'ı güncel HEAD ise eski kodu backup tag ile saklar ve üretim dalını PT'nin kendi OAuth/PAT yetkisiyle normal fast-forward ilerletir. Başka owner, veri/client repo'su veya upstream güncelleme hedefi olamaz. Veri migrasyonu gereken release otomatik açılmaz. Güncelleme kodu aktarma ve Vercel yayınının başarılı olması ayrı durumlardır.
